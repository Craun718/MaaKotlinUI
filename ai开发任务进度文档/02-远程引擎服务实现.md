## 1. RemoteServiceImpl：引擎主服务

```kotlin
class RemoteServiceImpl : RemoteService.Stub() {   // ← 无参构造！Shizuku/Root 反射实例化
    init {
        RemoteBootTrace.mark("CTOR_START")
        Runtime.getRuntime().addShutdownHook(Thread {
            runCatching { performEmergencyCleanup() }   // 进程退出兜底清理
        }.apply { name = "remote-shutdown-hook" })
    }

    init {
        Workarounds.apply()                    // hidden API 绕过
        startHeartbeatWatchdog()               // /proc 看门狗
        Ln.i("RemoteServiceImpl init, version: ${MaaCoreManager.maaService.GetVersion()}")
    }

    override fun destroy() {
        if (!destroyed.compareAndSet(false, true)) return
        InputControlUtils.setTouchCallback(null)
        performEmergencyCleanup()              // 恢复音频/销毁 Power/Screen/MaaCore
        exitProcess(0)
    }
}
```

### 为什么无参构造

- Shizuku 服务端 `UserService.create()` 优先 `(Context)` 构造器，否则无参构造；
- 参考项目 选择**无参构造 + 静态 `MaaCoreManager`**，context 用 `FakeContext.get()`（见下文），
  彻底摆脱"构造器 Context 从哪来"的麻烦，也规避了 `context.applicationContext` 为 null 的坑。

### 心跳看门狗（heartbeat watchdog）

```kotlin
private fun startHeartbeatWatchdog() {
    Thread {
        while (!destroyed.get()) {
            Thread.sleep(HEARTBEAT_INTERVAL_MS)   // 5s
            val pid = appPid.get()
            if (pid <= 0) continue
            if (!File("/proc/$pid").exists()) {   // App 进程没了 → 自我销毁
                destroy(); return
            }
        }
    }.apply { name = "remote-heartbeat-watchdog"; isDaemon = true }.start()
}
```

- App 侧 `service.heartbeat(Process.myPid())` 把 App pid 喂给引擎；
- 引擎每 5s 检查 `/proc/<pid>`；App 被杀 → 引擎自杀（不残留孤儿进程）。
- Root 模式下 `RootServiceStarter.primeHeartbeat` 提前喂 pid。

### performEmergencyCleanup（紧急清理）

```kotlin
fun performEmergencyCleanup() {
    runCatching {
        GameAudioMuteController.restoreAll()   // 恢复被静音的游戏
        PowerController.destroy()              // 释放虚拟屏保亮
        ScreenManager.destroy()
        MaaCoreManager.destroy()               // AsstDestroy 实例
    }
}
```
任何路径（destroy/看门狗/shutdown hook）退出都先清理，避免残留虚拟屏/静音。

## 2. 引擎侧 Context：FakeContext

引擎进程（shell/root uid）没有真实 App 上下文，参考项目 造了一个"假 context"：

```kotlin
class FakeContext : ContextWrapper {
    companion object { const val PACKAGE_NAME = "com.android.shell" }  // 冒用 shell 包名

    private constructor() { super(Workarounds.getSystemContext()) }   // 系统上下文兜底

    override fun getPackageName() = PACKAGE_NAME
    override fun getApplicationContext() = this                       // 非 null！
    override fun checkCallingPermission(p) = PERMISSION_GRANTED       // 永远放行
    override fun getAttributionSource() = AttributionSource.Builder(SHELL_UID).build()
    // getContentResolver 用 ActivityManager.getContentProviderExternal 实现
}
```

- `getApplicationContext() = this`：**保证 `context.applicationContext` 永不为 null**——这正是
  "引擎进程里调 `applicationContext.getSharedPreferences` NPE" 的根治方案（参考项目 从根上规避）。
- 冒用 `com.android.shell` 包名，让系统认为引擎是 shell 身份，绕过 UID/PKG 校验。
- ContentResolver 走 `getContentProviderExternal`（shell 权限可取外部 provider）。

## 3. MaaCoreManager：静态加载 libMaaCore.so

```kotlin
object MaaCoreManager {
    val MaaContext: MaaCoreLibrary? by lazy {
        runCatching {
            System.setProperty("jna.tmpdir", "/data/local/tmp")   // JNA 解包 so 到可执行目录
            RemoteBootTrace.mark("MAA_LOAD_BEGIN")
            Native.load("MaaCore", MaaCoreLibrary::class.java)    // JNA 加载 libMaaCore.so
        }.onFailure {
            RemoteBootTrace.mark("MAA_LOAD_FAIL", "...")
        }.getOrNull()
    }
    val maaService: MaaCoreServiceImpl = MaaCoreServiceImpl(MaaContext)
}
```

- `lazy` 惰性加载：第一次访问才 Native.load；
- `jna.tmpdir=/data/local/tmp`：JNA 解包临时 so 不能进 App 私有目录（shell uid 无权限）；
- 加载失败打 RemoteBootTrace 标记，不崩溃。

## 4. MaaCoreServiceImpl：Asst API 的 AIDL 封装

把 `libMaaCore.so` 的 Asst* 函数封装成 AIDL 接口（MaaCoreService），App 侧通过引擎调用：

```kotlin
class MaaCoreServiceImpl(private val ctx: MaaCoreLibrary?) : MaaCoreService.Stub() {
    private val instance = AtomicReference<Pointer>()          // AsstCreateEx 返回的句柄
    private val callback = AtomicReference<MaaCoreCallback?>()

    // native 回调：先转发 App（onCallback），再写日志——转发优先，日志不挡路
    private val nativeRef = AsstApiCallback { msg, json, _ ->
        val forwarded = runCatching { callback.get()?.onCallback(msg, json) }
        Ln.i("Callback: $msg, ${abbreviate(json)}")
    }

    override fun CreateInstance(cb: MaaCoreCallback?): Boolean {
        if (instance.get() != null) DestroyInstance()          // 单实例，先销毁旧
        callback.set(cb)
        instance.set(core.AsstCreateEx(nativeRef, null))
        return instance.get() != null
    }

    override fun AsyncConnect(adbPath, address, config, block) = core.AsstAsyncConnect(handle, ...)
    override fun AppendTask(type, params): Int = core.AsstAppendTask(handle, type, params)
    override fun Start() = core.AsstStart(handle)
    override fun Stop() = core.AsstStop(handle)
    override fun Running() = core.AsstRunning(handle)
    // GetImage 用 MemoryFile + ParcelFileDescriptor 跨进程传图
}
```

### 跨进程传图（GetImage → MemoryFile → PFD）

```kotlin
private fun getImageInternal(getImageFunc): ParcelFileDescriptor? {
    val buffer = Memory(DEFAULT_IMAGE_BUFFER_SIZE)   // 3840x2160x4
    val actualSize = getImageFunc(buffer, SIZE)
    val memoryFile = MemoryFile("maa_image", actualSize)
    memoryFile.writeBytes(...)
    val fd = getFileDescriptor(memoryFile)           // 反射 MemoryFile.getFileDescriptor
    return ParcelFileDescriptor.dup(fd)
}
```

### 回调转发优先级

```kotlin
private val nativeRef = AsstApiCallback { msg, json, _ ->
    val forwarded = runCatching { callback.get()?.onCallback(msg, json) }
    Ln.i("$TAG: Callback: $msg, ...")
    forwarded.onFailure { Ln.e("Callback DROPPED, msg=$msg: ...") }
}
```
**先转发再记日志**：App 侧收到 TaskChainStart 后要回写任务参数（如 FightDropsRefresher），日志不能挡在回调前面。

## 5. DriverClass：native upcall 桥

`libMaaCore.so` 在 AndroidNativeController 模式下需要回调 Java 层执行"启动 App / 触摸 / 按键"，
`DriverClass` 就是这些 upcall 的静态入口（在引擎进程内被 JNI 调用）：

```java
public static boolean startApp(String packageName, int displayId, boolean forceStop) {
    if (displayId == PrimaryDisplayManager.DISPLAY_ID) {
        return ActivityUtils.startApp(packageName, displayId, forceStop);      // 主屏
    }
    boolean ret = ActivityUtils.startApp(packageName, displayId, forceStop, true);  // 虚拟屏
    if (ret) {
        // 部分 ROM 会把游戏从虚拟屏挪回主屏 → 启动后校验并拉回；拉不回快速失败
        ret = ActivityUtils.ensureAppOnDisplay(packageName, displayId);
    }
    if (ret) awaitFirstFrame();    // 等首帧（getFrameCount 增长），避免识别空转
    return ret;
}

public static boolean touchDown/Move/Up/keyDown/keyUp(...) {
    return InputControlUtils.down/move/up/keyDown/keyUp(x, y, displayId);
}
```

要点：
- **startApp 后 ensureAppOnDisplay**：防游戏漂移（One UI 等 ROM 会把游戏挪回主屏）——与火影 MAA 的 `StartGameToVirtualDisplay` 同一思路，但 参考项目 把它做进了 **MaaCore 的 upcall 层**，所有走 MaaCore 的游戏启动路径都自动受保护。
- **awaitFirstFrame**：等画面流动（5s 超时），避免 screencap 空帧导致识别卡死。

## 6. 权限授予（引擎进程代授）

引擎以 shell/root 身份，可替 App/游戏授予系统权限（省电豁免、后台不受限、通知等）：

```kotlin
override fun grantPermissions(request: PermissionGrantRequest): PermissionStateInfo {
    val pkg = request.packageName; val uid = ...
    with(PermissionGrantHelper) {
        return PermissionStateInfo(
            accessibilityPermission = if (p & PERM_ACCESSIBILITY != 0) grantAccessibilityService(...),
            floatingWindowPermission = if (p & PERM_FLOATING_WINDOW != 0) grantFloatingWindowPermission(pkg, uid),
            notificationPermission = ...,
            batteryOptimizationExempt = ...,
            storagePermission = ...,
            backgroundUnrestricted = ...,
        )
    }
}
```
任务启动前 `grantGameBatteryExemption(clientType)` 给游戏授予省电豁免 + 后台不受限，让游戏新进程一启动就受保护。

## 7. 双模式虚拟屏入口（RemoteServiceImpl 视角）

```kotlin
override fun startVirtualDisplay(): Int = when (virtualDisplayMode.get()) {
    PRIMARY    -> PrimaryDisplayManager.start()     // 前台：物理屏模式
    BACKGROUND -> VirtualDisplayManager.start().also { id ->
        if (id != DISPLAY_NONE) PowerController.startUserActivityKeepAlive(id)  // 保亮
    }
    else -> DISPLAY_NONE
}

override fun setVirtualDisplayMode(mode): Boolean {
    when (mode) {
        PRIMARY    -> { VirtualDisplayManager.stop();  virtualDisplayMode.set(mode) }
        BACKGROUND -> { PrimaryDisplayManager.stop();  virtualDisplayMode.set(mode) }
    }
}
```

## 8. 给复现者的要点清单

1. 引擎服务**无参构造** + 静态初始化，避免 Context 注入问题。
2. `FakeContext`：`getApplicationContext()=this`、包名冒用 `com.android.shell`、永远放行权限。
3. `jna.tmpdir=/data/local/tmp` 必须设，否则 JNA 解包 so 失败。
4. 心跳看门狗：App pid + `/proc` 检查，App 死则引擎自杀。
5. shutdown hook + performEmergencyCleanup：任何退出路径都恢复音频/释放虚拟屏/销毁 MaaCore。
6. MaaCore 回调**先转发再记日志**。
7. 跨进程传图用 MemoryFile + ParcelFileDescriptor。
8. **DriverClass upcall 里做 startApp + ensureAppOnDisplay + awaitFirstFrame**——防漂移是引擎 upcall 层的职责。
