# 参考项目 深度拆解 05：虚拟屏与双模式运行

> 前台（物理屏）与后台（虚拟显示器）两种运行模式；虚拟屏创建 flags、防漂移、保亮、分辨率、旋转处理。

---

## 1. 双模式总览

| 模式 | DisplayMode | 游戏跑在哪 | 特点 |
|---|---|---|---|
| 前台 | PRIMARY | 物理屏（display 0） | 用户可见，悬浮窗控制 |
| 后台 | BACKGROUND | 虚拟显示器 | 无界面运行，可息屏 |

- `RemoteServiceImpl.setVirtualDisplayMode(mode)` 切换：切 PRIMARY 时停虚拟屏、切 BACKGROUND 时停物理屏模式。
- `startVirtualDisplay()` 按模式分发；后台模式额外 `PowerController.startUserActivityKeepAlive(displayId)`。

## 2. VirtualDisplayManager（后台虚拟屏）

### 创建流程

```kotlin
fun start(): Int {
    if (!state.compareAndSet(IDLE, CAPTURING)) return displayId.get()   // 防重入
    return startInternal()
}

private fun startInternal(): Int {
    val surface = NativeBridgeLib.setupNativeCapturer(cfg.width, cfg.height)  // 原生捕获器
    createVirtualDisplay(surface, cfg)
    return displayId.get()
}

fun restart() { releaseResources(); startInternal() }   // 分辨率变更/自愈重建

fun setResolution(w, h, dpi) {
    config.set(新值)
    if (CAPTURING && 变化) restart()                     // 分辨率变了自动重启
}
```

### 关键：flags 集合（防冻结/防黑屏）

```kotlin
private fun buildDisplayFlags(): Int {
    var flags = PUBLIC or PRESENTATION or OWN_CONTENT_ONLY or SUPPORTS_TOUCH
    if (VD_DESTROY_CONTENT) flags = flags or DESTROY_CONTENT_ON_REMOVAL
    if (VD_SYSTEM_DECORATIONS) flags = flags or SHOULD_SHOW_SYSTEM_DECORATIONS
    if (SDK >= 33) {   // Android 13+
        flags = flags or TRUSTED or OWN_DISPLAY_GROUP or ALWAYS_UNLOCKED
            or TOUCH_FEEDBACK_DISABLED
        if (SDK >= 34) {   // Android 14+
            flags = flags or OWN_FOCUS or DEVICE_DISPLAY_GROUP or STEAL_TOP_FOCUS_DISABLED
        }
    }
    return flags
}
```

- **PUBLIC + PRESENTATION + SUPPORTS_TOUCH**：虚拟屏可承载 Activity、支持触摸注入。
- **OWN_CONTENT_ONLY**：只显示投到该屏的内容。
- **DESTROY_CONTENT_ON_REMOVAL**：释放时销毁内容。
- **Android13+ 的 TRUSTED / ALWAYS_UNLOCKED / OWN_FOCUS / STEAL_TOP_FOCUS_DISABLED**：
  防系统把虚拟屏"当作未信任/未解锁/非焦点屏"而冻结渲染——**这是防虚拟屏黑屏的关键 flags**。

### 旋转处理（横屏原生设备）

## 3. PrimaryDisplayManager（前台模式）

前台模式不创建虚拟屏，而是：
- 返回物理屏 displayId（DISPLAY_ID）
- 可能设置强制显示尺寸/方向（setForcedDisplaySize 等，ScreenManager）
- 游戏直接跑在主屏，MaaCore 控制器照样通过 libbridge.so 截图/注入（display_id 用物理屏）

## 5. ActivityUtils：启动游戏 + 防漂移拉回

### startApp（带 displayId 启动）

```kotlin
fun startApp(packageName, displayId, forceStop=true, excludeFromRecents=true): Boolean {
    val intent = pm.getLaunchIntentForPackage(packageName) ?: getLeanbackLaunchIntent...
    intent.addFlags(NEW_TASK | (EXCLUDE_FROM_RECENTS if exclude))
    if (forceStop) am.forceStopPackage(packageName)      // 可选强制重启
    return startActivity(intent, displayId)
}

fun startActivity(intent, displayId, forceFullscreen=false): Boolean {
    val launchOptions = ActivityOptions.makeBasic()
    if (displayId != DEFAULT_DISPLAY) {
        launchOptions.launchDisplayId = displayId
        if (forceFullscreenOnVirtualDisplay || forceFullscreen) {
            // 反射 ActivityOptions.setLaunchWindowingMode(FULLSCREEN)
        }
    }
    val ret = am.startActivity(intent, launchOptions.toBundle())
    if (ret < 0) return startViaAmCommand(intent, displayId)   // 兜底 am start --display
    return true
}
```

### ensureAppOnDisplay（启动后校验 + 拉回）

```kotlin
fun ensureAppOnDisplay(packageName, displayId, timeout=10s): Boolean {
    while (true) {
        when (getAppDisplayId(packageName)) {
            null -> return true                    // 无法判断，宽松放行
            displayId -> return true
            DISPLAY_NO_TASK -> { /* 任务未出现，等待 */ }
            else -> return repinAppToDisplay(packageName, displayId)  // 漂移了 → 拉回
        }
        if (超时) return true                       // 超时宽松放行
        sleep(500)
    }
}
```

### repinAppToDisplay（三级拉回）

```kotlin
fun repinAppToDisplay(packageName, displayId): Boolean {
    // 1. moveRootTaskToDisplay / moveStackToDisplay（hidden API，shell 有 MANAGE_ACTIVITY_TASKS）
    if (moveAppTaskToDisplay(...)) { sleep(1s); if (isAppOnDisplay) return true }
    // 2. am display move-stack 命令兜底
    // 3. 重新投放 launch intent（强制 FULLSCREEN），让系统 reparent 现有任务
    if (startActivity(intent, displayId, forceFullscreen=true)) { sleep(1s); if (isAppOnDisplay) return true }
    return false
}
```

### getAppDisplayId（探测游戏当前所在屏）

- API < Q 返回 null（宽松放行）
- 反射 `RunningTaskInfo.displayId` 字段
- 取**最近任务**（漂移时新任务落主屏，虚拟屏残留旧任务 → 取最近任务最准确）

## 6. DriverClass.startApp 集成（upcall 层防漂移）

```java
public static boolean startApp(String packageName, int displayId, boolean forceStop) {
    if (displayId == PRIMARY) return ActivityUtils.startApp(pkg, displayId, forceStop);
    boolean ret = ActivityUtils.startApp(pkg, displayId, forceStop, true);
    if (ret) ret = ActivityUtils.ensureAppOnDisplay(pkg, displayId);   // ← 防漂移
    if (ret) awaitFirstFrame();                                        // ← 等首帧
    return ret;
}
```

**结论**：所有走 MaaCore 的游戏启动路径（upcall）自动带"启动到虚拟屏 + 防漂移拉回 + 等首帧"，杜绝"游戏被 ROM 挪回主屏 → 虚拟屏黑屏 → 识别空转"。

## 7. 给复现者的要点清单

1. 双模式：PRIMARY（物理屏）/ BACKGROUND（虚拟屏），setVirtualDisplayMode 切换。
2. 虚拟屏 flags 必须带 Android13+ 的 TRUSTED/ALWAYS_UNLOCKED/OWN_FOCUS 等，防冻结黑屏。
3. 旋转：freezeRotation + setForcedDisplaySize（横屏原生设备）。
4. 分辨率变更自动 restart 虚拟屏。
5. PowerController 周期 userActivity 保亮，防虚拟屏黑屏。
6. 游戏启动一律 startApp(displayId) + ensureAppOnDisplay（防漂移）+ awaitFirstFrame（等首帧）。
7. repinAppToDisplay 三级：hidden API moveTask → am move-stack → 强制 FULLSCREEN 重投。
