# 火影 MAA 补充改造：适配性 / 运行顺序 / UI / 日志系统

> 16/17 号已覆盖 P0/P1 核心。本篇按你关注的四个维度补充：
> **Shizuku 适配、运行逻辑顺序、UI 信息、日志系统**，外加其他 ROM/机型适配性。
> 每项标注：现状 → 问题 → 建议。✅=已具备 🟡=需优化 ❌=缺失。

---

## 一、Shizuku 相关适配性

### S-1 🟡 init 块降权/提权噪音（误导排查）
- **现状**：`RemoteEngineServiceImpl` init 块无条件执行"降权到 App uid → 发 root 广播 → 提权回 root"（setresuid 反射）。无 root 的 shell 设备上必然失败，日志出现两条误导性警告（"降权失败/提权回 root 失败"）。
- **问题**：用户/开发者误以为权限有问题；且每次引擎启动做两次 setresuid 反射有极小风险。
- **建议**：`if (Process.myUid() == 0) { ... }` 仅在 root 进程执行；shell 模式直接跳过。

### S-2 🟡 首页/设置页不显示 Shizuku 运行模式
- **现状**：`ShizukuManager.isRunningAsRoot()` 已实现但 UI 未用；用户无法直观看到 Shizuku 是 adb/shell 还是 root 模式（23:38 那次正是模式错乱导致绑定失败）。
- **建议**：首页 EngineStatusCard 或设置页显示"Shizuku：adb/shell 模式 / root 模式"，与「运行模式（Shizuku/Root）」区分开，避免混淆。

### S-3 🟡 无 Shizuku 一键安装引导
- **现状**：仅文字提示"安装 Shizuku"；用户需自行去应用商店/官网。
- **建议**（参考 Meow）：assets 内置 `shizuku.apk`，检测到 `NOT_INSTALLED` 时引导一键安装（FileProvider + ACTION_VIEW）；`APP_NOT_RUNNING` 时引导启动。可加 `ShizukuStatus` 分级（READY/SUI/APP_NOT_RUNNING/NOT_INSTALLED）。

### S-4 🟡 无 Sui 支持
- **现状**：未检测 Sui（Magisk 的 Shizuku 模块）。
- **建议**：`Sui.init(pkg)` 检测，Sui 可用时视为 Shizuku READY（部分 root 用户走 Sui 而非 Shizuku App）。

### S-5 🟡 授权流程回调式嵌套（可用性优化）
- **现状**：`ShizukuManager.requestPermission(context, callback)` 回调式，业务中回调嵌套。
- **建议**：封装 `suspend fun requestPermission(): Boolean`（callbackFlow + withTimeoutOrNull(15s)），业务直读。

### S-6 ✅ 其他已具备
- preV11 兼容、binder 存活/授权检测、binder 状态监听、isRunningAsRoot、isAppInstalled。

## 二、运行逻辑顺序

### O-1 🟡 资源部署时机（首次/更新后点开始任务要等 1-3s）
- **现状**：`startEnabledTasks` 里 `AssetResourceDeployer.deploy()`（点击才部署）；首次安装/版本更新后，用户点开始任务会先等部署（1-3s）且部署失败则任务直接失败。
- **建议**（参考 Meow）：`Application.onCreate` 后台线程预部署（进程启动即执行，不依赖 UI），
  `checkAndInit` 幂等：已就绪（`.maafw_version` 匹配）跳过。点开始任务时基本零等待。

### O-2 🟡 AsyncConnect 同步阻塞风险
- **现状**：火影 `MaaFrameworkEngine.createController` 直接 `MaaControllerPostConnection + MaaControllerWait`（同步阻塞，无超时）；控制器连接慢/挂起时主流程卡死。
- **建议**（参考 Meow）：`AsyncConnect` + `AsyncCallInfo` 回调驱动 + 2s 超时；失败给出"控制器连接失败"分级提示。

### O-3 🟡 停止任务不等 MaaCore 真正停止
- **现状**：`stopRemoteEngine` 调 `stopTask()` 后立即 closeGame/stopVirtualDisplay。
- **建议**（参考 Meow）：`AsstStop` 后轮询 `maa.Running()` 至多 60s 再收尾，避免任务未完全停止就拆虚拟屏。

### O-4 🟡 手动任务与定时任务引擎状态不共享
- **现状**：`MainActivity` 与 `MaaEngineService` 各自维护 `remoteService/remoteBound`，可能状态不一致（一边绑着、一边又绑）。
- **建议**（参考 Meow）：收敛为单一 `RemoteServiceManager` 状态机（P0-6），两处都走它。

### O-5 🟡 引擎复用（reuse）与"暂停恢复"状态残留
- **现状**：引擎复用开启时跨任务复用 tasker；暂停恢复走特殊分支。偶发"旧识别结果/旧状态"影响。
- **建议**：复用前 `clearCache + reConnectController` 已有；可增加"异常结束强制重建"兜底（已有 needRebuild），保持现状即可，重点验证 pause/resume 路径。

### O-6 ✅ 已具备
- 绑定成功自动重设预览 Surface；帧停滞 15s 自愈（重亮+重建预览）；暂停恢复虚拟屏复用；游戏预启动到虚拟屏 + 等首帧。

## 三、UI 信息优化

### U-1 🟡 引擎连接状态不完整（缺"绑定中/失败原因"）
- **现状**：开始任务按钮已禁用并显示"引擎连接中…/引擎未连接"，但首页 EngineStatusCard 无绑定中状态、无失败原因展示。
- **建议**：EngineStatusCard 增加：绑定中（转圈）、失败（显示简短原因+一键重试/重启 Shizuku 引导）。

### U-2 🟡 失败提示不够可操作
- **现状**：绑定失败已有 5 条提示，但散在日志里；虚拟屏/控制器/资源失败无分级提示。
- **建议**：落地 P1-3（StartResult 分级），失败时弹窗/卡片给出**下一步操作**（如"①重启 Shizuku ②澎湃设置自启动 ③切 Root"）。

### U-3 🟡 日志页纯文本（无时间/级别/搜索）
- **现状**：脚本页日志纯文本列表。
- **建议**（参考 Meow）：日志行带时间戳+级别颜色（INFO/SUCCESS/WARN/ERROR），支持筛选/搜索/一键复制。

### U-4 🟡 任务通知无进度
- **现状**：`TaskNotificationCoordinator` 发"开始/完成/失败"通知，无进行中进度。
- **建议**（参考 Meow）：`NotificationCompat.ProgressStyle` 分段进度条（按任务链数），进行中每 1s 节流更新；Android14+ 可提升为 Live Update。

### U-5 🟡 首次引导缺 Shizuku 状态门
- **现状**：Onboarding 引导授权/权限，但 Shizuku 未装/未启动时无强引导。
- **建议**（参考 Meow ShizukuReadinessGate）：首次进入核心页面前按状态门：未装→装、未启动→启动、未授权→授权；未就绪禁用核心操作。

### U-6 🟡 设置页"运行模式"切换后无提示
- **现状**：Shizuku↔Root 切换后需重启 App/重绑，但无提示。
- **建议**：切换时提示"已切换为 Root 模式，将重启引擎连接"，并自动重绑。

### U-7 ✅ 已具备
- 首页引擎状态卡（待机/运行中/连接/Agent）、分辨率显示、触摸预览、全屏预览、悬浮导航、开始按钮禁用（绑定中）。

## 四、日志系统

### L-1 ❌ 无 CrashHandler（App 崩溃无兜底记录）
- **现状**：无 `Thread.setDefaultUncaughtExceptionHandler`。
- **问题**：App 崩溃原因不可见（尤其引擎绑定/任务执行时主进程崩溃）。
- **建议**：Application 启动注册 CrashHandler，把异常写入 `{ext}/files/debug/crash.log`（含线程/堆栈/版本），导出日志时带上。

### L-2 ❌ 无三层诊断日志（绑定链路/引擎启动）
- 同 P1-1：ServiceBootLogger（App 绑定）+ RemoteBootTrace（引擎启动，路径自行推导）+ root_launch_debug.log。

### L-3 ❌ logcat 抓取返回空（用户"43 字节"现象）
- 同 P1-2：独立 logcat 服务进程按 pid 过滤（`logcat -T 10 --pid=<appPid>/<servicePid>` 落盘），
  替代现在的一次性 dump（权限/过滤问题）。

### L-4 🟡 导出为散文件，无设备信息
- **现状**：导出按文件名复制（app/maafw/logcat）。
- **建议**（参考 Meow）：打包 ZIP（含 debug 全部日志），debugMode 附 `getprop` 设备信息；保留最近 N 份。

### L-5 🟡 无会话日志概念
- **现状**：logBuffer 简单列表（上限 500），无会话开始/结束/状态。
- **建议**（参考 Meow）：引入会话日志（startSession/append/endSession(status)），任务从开始到结束一条链路，UI 可回看。

### L-6 🟡 日志级别无全局控制
- **现状**：`Ln` 级别固定；debugMode 未联动日志量。
- **建议**：debugMode 开启时输出 DEBUG/VERBOSE，关闭时 INFO 起；导出时自动带全量。

### L-7 ✅ 已具备
- maafw.log 会话轮转（rotateEngineLog）、custom_kt.log、导出目录清理、focus 日志轮询（tail maafw.log）、引擎日志滚动备份。

## 五、其他 ROM/机型适配性

### R-1 🟡 游戏包名硬编码（com.tencent.KiHan）
- **现状**：`prelaunchGame`/`Startup.json`/`stopPackage` 等硬编码；若游戏有渠道包/改名，需改代码。
- **建议**：统一为常量/配置（设置页可改），Meow 用 `Packages[clientType]` 映射。

### R-2 🟡 虚拟屏无 rotation 处理（横屏原生设备）
- **现状**：火影 VirtualDisplayManager 无 `freezeRotation`/`setForcedDisplaySize` 处理。
- **建议**（参考 Meow）：创建虚拟屏后若 `display.rotation != 0` → `freezeRotation(ROTATION_0)`；
  物理屏自然方向 0 而虚拟屏有旋转（横屏原生设备如掌机）→ `setForcedDisplaySize` 强制横屏上报。

### R-3 🟡 物理屏熄亮只操作主屏
- **现状**：`setDisplayPower` 若只操作主屏，折叠屏/双屏设备另一屏可能残留点亮。
- **建议**（参考 Meow）：Android10+ 遍历物理屏熄亮；荣耀 Android14 特判（跳过遍历，防误关内置屏）。

### R-4 🟡 无 ConfigurationController 填充（三星 getDisplayInfo）
- **现状**：火影 `Workarounds` 需核对是否包含 `mConfigurationController` 填充。
- **建议**：Android12+ 填充 `ConfigurationController`（scrcpy#4467 三星 getDisplayInfo NPE 修复）。

### R-5 🟡 分辨率模板与虚拟屏配置一致性
- **现状**：支持 720p/1080p/custom；游戏内识别模板按分辨率匹配。
- **建议**：确保"虚拟屏分辨率=识别模板分辨率"强一致；custom 时给出模板适配提示。

### R-6 🟡 无后台"省电策略"引导（自身 App）
- **现状**：首次引导有电池优化豁免；但国产 ROM 的"自启动/后台运行"（澎湃/vivo 专属）未引导。
- **建议**：检测厂商（`Build.MANUFACTURER`）→ 给出对应 ROM 的后台白名单引导页（参考 Meow 提示文案）。

### R-7 ✅ 已具备
- 虚拟屏全 flags + 失败降级 + requestDisplayPower 点亮；触摸 CANCEL 防护 + ASYNC 适配；
  坐标 clamp/重试；隐藏 API Workarounds；Android 版本分支。

## 📋 优先级建议（补充项）

```
第一批（成本低、见效快）：
  S-1 init 降权噪音过滤（1 行 if）
  L-1 CrashHandler（0.5h）
  O-1 资源预部署（进程启动后台做）
  U-1 首页连接状态 + 失败一键重试
  R-1 游戏包名常量/配置

第二批（体验/可诊断）：
  S-2 首页显示 Shizuku 模式、S-3 一键装 Shizuku、S-4 Sui、S-5 suspend 授权
  O-2 AsyncConnect 超时、O-3 停止等 Running、O-4 状态机共享
  U-3 日志时间/级别、U-4 通知进度条、U-5 就绪门、U-6 切换提示
  L-4 导出 ZIP+设备信息、L-5 会话日志、L-6 日志级别控制

第三批（深水区）：
  R-2 rotation、R-3 多屏熄亮、R-4 ConfigurationController、R-6 ROM 白名单引导
```

> 先做第一批（S-1/L-1/O-1/U-1/R-1）性价比最高，且大多不碰引擎核心链路，风险低。
