## 0. 术语与引擎独立性说明（必读）

- **参考项目**：本系列分析的**外部参考实现**（原项目名已隐去）。它是一个 Android 原生游戏助手：
  基于 **MAA（MaaAssistantArknights）引擎（`libMaaCore.so`，Asst* API）**，目标游戏为明日方舟，
  通过 Shizuku/Root 获得 shell 权限、双模式（前台/后台虚拟屏）运行。
- **火影 MAA 项目**（`com.maafw.naruto`）：我们的项目，目标游戏为火影忍者手游，
  使用 **MaaFW（MaaFramework，`libMaaFramework.so`，Maa* API：MaaTaskerCreate/MaaControllerCreate 等）**。
- **两者是相互独立的项目、独立引擎、独立代码**。本系列**仅借鉴参考项目的架构、连接方案、适配经验**，
  不涉及引擎/代码复用；分析中出现的参考项目类名（如 `RemoteServiceImpl`、`MaaCoreServiceImpl`）与
  Asst* API 均属参考项目，落地到火影项目时需映射为 MaaFW 对应 API（如 `MaaTaskerCreate` 等）。
- 文档中"参考项目引擎（MAA）"与"火影引擎（MaaFW）"不混用；涉及引擎差异处会单独标注。

## 1. 项目是什么

参考项目（`com.refproject`）是一个 **Android 原生运行 MAA（明日方舟助手）** 的应用：

- 无需 Root，**Shizuku**（adb/shell 权限）即可后台运行游戏自动化
- 也支持 **Root** 模式（liblauncher.so + app_process 拉起 root 引擎进程）
- 双模式：**前台模式**（游戏跑在物理屏，悬浮控制）与**后台模式**（游戏跑在虚拟显示器，无界面运行）
- 基于图像识别，自动完成明日方舟日常（理智/公招/基建/肉鸽/抄作业等）

**技术本质**：把 PC 版 MAA 的"模拟器 + adb 控制"替换为"Android 本机 + Shizuku/Root 的 shell 权限"，用 JNA 直接调用 `libMaaCore.so`，通过 `libbridge.so`（NativeBridgeLib）完成虚拟屏截屏与触摸注入。

## 2. 进程模型（最关键的设计）

应用由 **3 类进程** 组成：

```
┌─────────────────────────────────────────────────────────────┐
│ App 进程（com.refproject）                           │
│   UI / 设置 / 任务编排 / 资源管理 / 日志汇总                  │
│   RemoteServiceManager（连接状态机）                         │
└──────────────┬──────────────────────────────────────────────┘
               │ binder（AIDL: RemoteService / MaaCoreService）
               ▼
┌─────────────────────────────────────────────────────────────┐
│ 引擎进程（Shizuku UserService 或 Root app_process）          │
│   RemoteServiceImpl（无参构造，FakeContext）                 │
│   ├─ MaaCoreServiceImpl（JNA 封装 libMaaCore.so）           │
│   ├─ VirtualDisplayManager / PrimaryDisplayManager（显示）   │
│   ├─ PowerController（保亮/userActivity）                   │
│   └─ ActivityUtils（启动游戏/防漂移拉回）                    │
└──────────────┬──────────────────────────────────────────────┘
               │ 同进程直调（JNA upcall）
               ▼
┌─────────────────────────────────────────────────────────────┐
│ 原生层：libMaaCore.so（MaaFramework）+ libbridge.so（capturer/注入）│
└─────────────────────────────────────────────────────────────┘
```

关键点：**MaaCore 只活在引擎进程**，App 进程绝不加载巨大的 MaaCore so（避免 ANR/内存）；App 通过 AIDL 调用引擎，引擎把截图/识别/触摸全部在本进程完成。

### 第三个进程：Logcat 服务进程
`LogcatCaptureServiceImpl` 也作为独立 UserService/root 进程运行，专门抓取全量 logcat（引擎进程自身日志 + App 日志），避免 App 进程 logcat 权限不足。

| `overlay/` `presentation/` `schedule/` | 悬浮窗、UI、定时任务 |


## 6. 技术栈

- **Kotlin + Jetpack Compose**（UI）、**Koin**（DI）、**kotlinx.serialization / fastjson2**（JSON）
- **rikka.shizuku:api:13.x**（Shizuku 客户端）、**rikka.sui**（Sui root 检测）
- **JNA 5.x**（调用 libMaaCore.so / libbridge.so / liblauncher.so）
- **libtopjohnwu.superuser:io**（Root 的 Shell 执行）
- **Timber**（日志）、**coroutines**（异步）

## 7. 设计哲学（贯穿全项目的关键决策）

1. **一切重活放引擎进程**：MaaCore 加载、识别、截图、注入全在 UserService/root 进程；App 只做编排与展示。
2. **绑定必带随机 tag + 递增 version**：Shizuku 服务端按 `package:tag` 记 record，随机 tag 保证每次绑定都是全新 key，**根治"首次成功之后全部超时"**（服务端 record 卡死）。
3. **独立 ServiceConnection + stale 检查**：每次绑定新 connection，回调里校验 `activeBinding?.connection === this`，忽略过期回调。
4. **双通道可切换**：Shizuku / Root 后端由 `RemoteAccessCoordinator` 统一管理，UI 无感切换。
5. **进程侧自诊断**：App 侧 `ServiceBootLogger`（service_bind_debug.log）+ 引擎侧 `RemoteBootTrace`（service_boot_debug.log）+ Root 启动 `root_launch_debug.log`，三层日志定位"绑不上/起不来/连不上"。
6. **看门狗三层**：App 心跳（heartbeat + /proc 检查）、引擎 shutdown hook（紧急清理）、AppWatchdog（游戏进程/显示漂移检测）。
7. **不信任系统**：所有 hidden API 用反射/Workarounds 兼容；虚拟屏创建带全套 flags（Android13+ TRUSTED/ALWAYS_UNLOCKED 等）防冻结。
