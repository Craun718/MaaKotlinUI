# MAA-Meow 后台防杀保活方案深度分析与移植建议（22）

> 日期：2026-08-14
> 来源：通读 MAA-Meow-main（参考项目）保活相关源码后的分析。
> 目的：拆解 Meow 的防杀保活体系，对比火影 MAA 现状，提炼可借鉴的增强点。

---

## 一、Meow 保活体系总览（4 层）

```
┌─ 第1层：无障碍防杀（AccessibilityHelperService）→ App 进程受系统保护（非 root 有效）
├─ 第2层：前台服务（TaskExecutionService / ScheduleExecutionService）→ App 常驻（FGS 竞态防护）
├─ 第3层：引擎虚拟屏保亮（PowerController userActivity）→ 虚拟屏不灭、引擎被感知
└─ 第4层：权限代授（PermissionManager + 引擎 shell）→ 一键授予电池优化/无障碍/后台不受限
```

---

## 二、逐组件详解

### 1. AccessibilityHelperService（无障碍防杀 + 功能）

**文件**：`service/AccessibilityHelperService.kt`

| 设计点 | 实现 | 价值 |
|---|---|---|
| **防杀** | AccessibilityService（`canRetrieveWindowContent=false`，不读屏幕） | App 进程被系统标记"重要"，ColorOS/各家不杀（**非 root 有效**） |
| **音量键快捷** | `onKeyEvent` 监听 **音量+ / 音量- 同时按**（300ms 容差）→ 触发回调 | 后台挂机时物理键快捷操作（开始/停止任务） |
| **状态观察** | `isConnected: StateFlow<Boolean>` | UI 实时显示无障碍是否开启，驱动引导 |
| **配置入口** | `android:settingsActivity="...MainActivity"` | 无障碍设置页点服务 → 直接进 App |

**配置**（`accessibility_helper_service_config.xml`）：
```xml
android:accessibilityEventTypes="typeAllMask"
android:canRetrieveWindowContent="false"        ← 不读屏幕（隐私友好）
android:canRequestFilterKeyEvents="true"        ← 允许拦截音量键
android:settingsActivity="com.aliothmoon.maameow.MainActivity"
```

### 2. TaskExecutionService（前台服务，FGS 竞态防护）

**文件**：`domain/service/TaskExecutionService.kt`

```kotlin
// 关键：先 startForeground 再做任何可能 stop 的逻辑（防 FGS 竞态被系统杀）
startAsForeground(buildNotification(initial))
```
- 只提供 start，不提供外部 stop（防止 startForegroundService 后 stopService 抢跑 → 系统杀进程）
- 通知节流更新（forceUpdate / throttledUpdate 1s）

### 3. ScheduleExecutionService（定时任务前台服务）

**文件**：`schedule/service/ScheduleExecutionService.kt`
```kotlin
startForeground(NOTIFICATION_ID, notification,
    ServiceInfo.FOREGROUND_SERVICE_TYPE_SPECIAL_USE)  // Android 14+ 类型
```
- 定时任务也走前台服务（SPECIAL_USE 类型，Android14+ 合规）

### 4. PowerController（引擎虚拟屏保亮）

**文件**：`remote/internal/PowerController.kt`
- 引擎进程（shell）周期性 `userActivity(displayId)`（4s）保亮虚拟屏
- 防止 Doze 灭屏 → 虚拟屏黑屏 → 识别中断

### 5. PermissionManager.quickGrantAccessibility（**引擎 shell 代授无障碍**）

**文件**：`manager/PermissionManager.kt`

```kotlin
suspend fun quickGrantAccessibility(): Boolean {
    if (!permissions.remoteAccessGranted) return false
    return try {
        val result = RemoteServiceManager.useRemoteService { srv ->
            srv.grantPermissions(
                PermissionGrantRequest(
                    packageName = context.packageName,
                    uid = context.applicationInfo.uid,
                    accessibilityServiceId = AccessibilityHelperService.SERVICE_ID,  // ← 无障碍服务 ID
                    permissions = PERM_ACCESSIBILITY                                // ← 无障碍权限位
                )
            )
        }
        if (result.accessibilityPermission) {
            withTimeoutOrNull(3000L) {
                AccessibilityHelperService.isConnected.filter { it }.first()        // ← 等无障碍连接
            }
        } else false
    } ...
}
```

**核心**：通过**引擎进程（shell/root 身份）写 `Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES`** 直接启用无障碍服务，**用户无需手动进系统设置**！root/Shizuku root 可写；Shizuku shell（uid2000）通常也有权限（shell 可写部分 secure settings）。

### 6. 引擎进程（RemoteServiceImpl）——Meow 未直接防杀

grep 显示 Meow 引擎进程**没有 oom_adj/唤醒锁**，靠：
- App 前台服务 + 无障碍 → App 进程重要
- 引擎是 App 的 bound service（Shizuku UserService）→ 系统按客户端（App）重要性计算 adj
- 虚拟屏保亮（userActivity）保持引擎活跃

## 三、对比火影 MAA 现状

| 维度 | Meow | 火影 MAA | 差距 |
|---|---|---|---|
| 无障碍防杀 | ✅（+音量键快捷+状态观察+settingsActivity） | ✅ 纯防杀（无音量键/状态观察） | 🟡 增强 |
| 无障碍**引擎代授一键开启** | ✅ **shell 写 secure settings** | ❌ 需用户手动进无障碍设置 | 🔴 **关键差距** |
| 前台服务（App 保活） | ✅ TaskExecutionService（FGS 防护） | ✅ KeepAliveService | ✅ |
| 定时任务前台服务 | ✅ ScheduleExecutionService（SPECIAL_USE） | ✅ MaaEngineService | ✅ |
| 引擎虚拟屏保亮 | ✅ userActivity 4s | ✅ startVdKeepAlive | ✅ |
| 引擎 oom_adj | ❌ 无（依赖 App） | ✅ root 下 -800 | ✅ 更强 |
| 断点续跑（引擎被杀恢复） | 无此机制（AppWatchdog 停任务） | ✅ 自动重连+断点续跑 | ✅ 更强 |

## 四、可借鉴的优化（火影 MAA 应移植）

### 优化 1（重要）：无障碍引擎代授一键开启

**现状**：火影需用户手动进系统无障碍设置开启（三处入口引导，但非一键）。
**Meow 方案**：引擎 shell 写 `Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` 直接启用。

**实现**：
1. AIDL `grantPermissions` 扩展无障碍位（PERM_ACCESSIBILITY=32，已有）+ `accessibilityServiceId` 参数
2. 引擎侧（shell/root）：
```kotlin
// 引擎 shell 写 secure settings 启用无障碍服务（root/shizuku root 可写；shell 尝试）
override fun grantPermissions(pkg, perms, accessibilityServiceId): ... {
    if (permissions and 32 != 0 && !accessibilityServiceId.isNullOrBlank()) {
        runCatching {
            val cmd = "settings put secure enabled_accessibility_services '$accessibilityServiceId'"
            Runtime.getRuntime().exec(arrayOf("sh", "-c", cmd))  // shell 身份执行
            // 或反射 Settings.Secure.putString（root 可写）
        }
    }
}
```
3. App 侧：设置页"无障碍防杀"→ **一键开启**（调引擎 grantPermissions + 等 KeepAliveAccessibilityService.onServiceConnected）
4. 开启后服务自动连接（系统绑定）→ onServiceConnected → 标记成功

**收益**：非 root 用户一键开启无障碍防杀（Shizuku shell 可写），体验大幅提升。

### 优化 2：无障碍状态实时观察 + 引导

- `KeepAliveAccessibilityService` 加 `isConnected: StateFlow<Boolean>`（onServiceConnected 置 true）
- 设置页"无障碍防杀"实时显示状态（已启用/未启用），不再靠手动刷新
- 首页权限检查同样实时

### 优化 3：音量键快捷操作（后台挂机快捷）

- 无障碍服务加 `onKeyEvent`：**音量+ / 音量- 同时按** → 触发回调（开始/停止任务）
- 后台挂机时物理键快捷开始/停止（不用打开 App）

### 优化 4：无障碍配置加 settingsActivity

- `accessibility_service_config.xml` 加 `android:settingsActivity` → 用户点无障碍服务可直达 App

## 五、火影 MAA 完整保活方案（当前 + 建议）

```
【已实现】
├─ 无障碍防杀（KeepAliveAccessibilityService，纯防杀）→ App 进程保护

【建议新增（参考 Meow）】
├─ 无障碍引擎代授一键开启（shell 写 secure settings）★ 最重要
├─ 无障碍状态 StateFlow 实时观察
├─ 音量键组合快捷（后台物理键操作）
└─ settingsActivity（无障碍配置直达 App）
```

## 六、结论

1. **Meow 的核心保活**：无障碍防杀 App + 前台服务 + 虚拟屏保亮，**不直接防引擎**（依赖 App 重要性）
2. **火影已更强**：多 oom_adj（root）+ 断点续跑（引擎被杀自动恢复）
3. **最大可借鉴**：**无障碍引擎代授一键开启**——消除"需手动进系统设置"的体验痛点，非 root 用户也能一键开启防杀
4. 次要借鉴：音量键快捷、无障碍状态实时观察、settingsActivity

> 下一步建议：实现"无障碍引擎代授一键开启"（AIDL 扩展 + 引擎写 secure settings + 一键按钮），并加音量键快捷。
