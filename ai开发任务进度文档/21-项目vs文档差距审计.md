### 方案 1：任务链分段进度（MaaFwTaskProgress）【参考 04/14 号】

**目标**：通知从"不确定进度条"升级为分段进度条（按任务链数）。

**涉及文件**（MaaFW 专属命名）：
- 新建 `data/task/MaaFwTaskProgress.kt`（任务链进度状态，类名 MaaFwTaskProgress）
- `aidl/com/maafw/naruto/IEngineStatusListener.aidl`（新增 onTaskEvent）
- `remote/RemoteEngineServiceImpl.kt`（事件统计 + notifyTaskEvent）
- `MainActivity.kt`（taskProgress 实例 + onTaskEvent 实现 + 任务开始 reset）
- `service/AppNotificationManager.kt`、`TaskNotificationCoordinator.kt`（分段进度通知）
- `ui/script/ScriptsScreen.kt`（可选 UI 进度展示）

**实现步骤**：
1. 引擎侧 `registerEventSink` 解析 `Tasker.Task.Starting/Succeeded/Failed` 的 details（entry 字段）：
   - Starting → 该任务 IN_PROGRESS
   - Succeeded → COMPLETED；Failed → ERROR
2. 新建 `TaskChainTracker`（App 侧，接收引擎回调）：
```kotlin
class TaskChainTracker {
    enum class Status { PENDING, IN_PROGRESS, COMPLETED, ERROR }
    data class TaskInfo(val taskId: Long, val entry: String, val status: Status)
    private val registry = LinkedHashMap<Long, TaskInfo>()
    private val _tasks = MutableStateFlow<List<TaskInfo>>(emptyList())
    val tasks: StateFlow<List<TaskInfo>> = _tasks.asStateFlow()
    fun register(taskId: Long, entry: String) { registry[taskId] = TaskInfo(taskId, entry, Status.PENDING); push() }
    fun updateStatus(taskId: Long, status: Status) { registry[taskId]?.let { it.status = status }; push() }
    fun clear() { registry.clear(); push() }
    private fun push() { _tasks.value = registry.values.toList() }
}
```
3. 引擎 AIDL 增加任务事件回调：`IEngineStatusListener` 扩展 `onTaskEvent(entry: String, event: Int)`（或复用现有 onLog 解析）。
4. App 侧：任务开始 `tracker.register(i, entry)`；收到事件 `updateStatus`。
5. 通知：`AppNotificationManager.notifyTaskRunning(taskName, completed, total)` 用 `setProgress(completed, total, false)` 分段进度。
6. 结束 `cancelTaskRunning()`。

**验证**：任务运行中通知显示分段进度（N 个任务，完成 X/N）；任务失败对应段标红。

override fun startCapture(appPid: Int, servicePid: Int, userDir: String) {
    val dir = File(userDir, "debug/logcat").apply { mkdirs() }
    listOf(servicePid to "core", appPid to "app").forEach { (pid, tag) ->

### 方案 4：连接状态机 + useRemoteService 统一入口【参考 01 号】

**目标**：收敛散落的绑定逻辑为单例状态机，提供 `useRemoteService{}` 统一入口（根治并发重连双进程）。

**涉及文件**：
- 新建 `manager/RemoteServiceManager.kt`（状态机单例）
- `MainActivity.kt` / `MaaEngineService.kt` 改为统一调用
- 删除/改造 `EngineConnectionShared`（并入状态机）

**实现步骤**：
```kotlin
object RemoteServiceManager {
    sealed class State { object Disconnected; object Connecting; object Died; class Connected(val svc: IRemoteEngineService); class Error(val e: Throwable) }
    private val _state = MutableStateFlow<State>(State.Disconnected)
    private val lock = Any()
    fun bind() { synchronized(lock) { if (_state.value is State.Connecting) return; /* 先解旧 */ unbindLocked(); _state.value = State.Connecting; connector.connect(callbacks) }; startConnectTimeout() }
    suspend fun <T> useRemoteService(block: (IRemoteEngineService) -> T): T? {
        val svc = getInstanceOrNull() ?: run { bind(); getInstance(15_000) } ?: return null
        return block(svc)
    }
    private val callbacks = object : ConnectorCallbacks {
        override fun onConnected(binder: IBinder) { synchronized(lock) { _state.value = State.Connected(Stub.asInterface(binder)) }; doOnConnected() }
        override fun onDisconnected() { synchronized(lock) { _state.value = State.Died }; autoRebind() }
        override fun onError(e: Throwable) { synchronized(lock) { _state.value = State.Error(e) }; autoRetry() }
    }
    // binder death → Died → 自动重绑；绑定失败 → 5s 重试（上限2）
}
```
2. `MainActivity` 任务启动/停止走 `useRemoteService {}`；`MaaEngineService` 同样。
3. 心跳/引擎共享写入集中到 `onConnected`。

**验证**：引擎崩溃 → 状态 Died → 自动重连；手动+定时并发不再双进程。

### 方案 7：Koin DI【参考 15 号】

**结论：当前不建议引入（YAGNI）。**

**理由**：
- 项目单模块、依赖简单（object 单例已满足：设置/引擎共享/日志/通知）；
- 无多模块拆分、无单元测试、无运行时多实现切换需求；
- 引入需联网加依赖 + 全量改造调用点（机械改动、风险大于收益）。

**何时再引入**：项目扩到多模块 / 需要单测 mock / 依赖图复杂化时。

**轻量替代**：需要测试时用"接口 + 构造器注入"（手动 DI，无框架）。

### 方案 12：完整回调分发（MaaCallbackDispatcher）【参考 14 号】

**目标**：把 MaaFramework 事件按类型分发到多个处理器（进度/日志/通知），替代单一 sink。

**涉及文件**：
- 新建 `maa/callback/MaaFwCallbackDispatcher.kt`
- `remote/RemoteEngineServiceImpl.kt`（sink 改为分发器）

**实现步骤**：
```kotlin
class MaaFwCallbackDispatcher {
    private val handlers = mutableListOf<(String, String?) -> Unit>()
    fun addHandler(h: (String, String?) -> Unit) { handlers.add(h) }
    fun dispatch(message: String, details: String?) { handlers.forEach { runCatching { it(message, details) } } }
}
// 处理器：TaskProgressHandler（方案1）、SessionLogHandler、NotifyHandler
```
2. 引擎 sink 收到事件 → dispatcher.dispatch → 各处理器。

**验证**：任务事件同时驱动进度/日志/通知，互不阻塞。
