# 参考项目 深度拆解 10：底层细节——系统服务访问与日志

> 引擎进程怎么拿系统服务？`ServiceManager` 统一反射入口 + 各 wrapper 的反射细节；
> `Ln` 双通道日志（logcat + stdout/stderr）的底层实现。

---

## 1. ServiceManager：统一系统服务入口

```java
public final class ServiceManager {
    private static final Method GET_SERVICE_METHOD;   // android.os.ServiceManager.getService(String)
    static {
        GET_SERVICE_METHOD = Class.forName("android.os.ServiceManager")
            .getDeclaredMethod("getService", String.class);
    }

    static IInterface getService(String service, String type) {
        IBinder binder = (IBinder) GET_SERVICE_METHOD.invoke(null, service);   // 拿 binder
        Method asInterface = Class.forName(type + "$Stub").getMethod("asInterface", IBinder.class);
        return (IInterface) asInterface.invoke(null, binder);                  // 转 AIDL 接口
    }

    // 单例缓存各 wrapper：
    public static WindowManager getWindowManager()      // WindowManager.create()
    public static synchronized DisplayManager getDisplayManager()  // 可能多线程用，加锁
    public static InputManager getInputManager()        // InputManager.create()
    public static PowerManager getPowerManager()        // PowerManager.create()
    public static StatusBarManager getStatusBarManager()
    public static ActivityManager getActivityManager()
    public static CameraManager getCameraManager()      // 反射构造（Context= FakeContext）
}
```

**底层事实**：`android.os.ServiceManager.getService(name)` 在 App 进程是 @hide（Android 9+ 被隐藏/限制），但**在 shell/root 身份的引擎进程可以直接反射调用**（无 hidden API 限制，或 shell 豁免）。这就是引擎进程能访问 `activity_task`、`display`、`input`、`power`、`window`、`statusbar`、`surfaceflinger` 等系统服务的原因。

## 2. wrappers 反射细节（按服务）

### InputManager（注入触摸/按键）

```java
// 拿 manager：FakeContext.get().getSystemService(INPUT_SERVICE)
// 反射方法（缓存到静态字段，只反射一次）：
injectInputEvent:  InputManager.injectInputEvent(InputEvent, int mode)   // mode: ASYNC/WAIT_FOR_RESULT/WAIT_FOR_FINISH
setDisplayId:      InputEvent.setDisplayId(int)                          // 指定目标屏（虚拟屏注入的关键）
setActionButton:   MotionEvent.setActionButton(int)
addUniqueIdAssociationByPort / removeUniqueIdAssociationByPort  // API 35 手柄/触控笔关联

// INJECT_EVENTS 权限错误：限频日志（3s 一次）+ 提示"USB调试（安全设置）"未开
```

### PowerManager（电源/userActivity/wakeUp）

```java
// manager = ServiceManager.getService("power", "android.os.IPowerManager")
isScreenOn:   API34+ isDisplayInteractive(int) / 旧 isInteractive()
userActivity: API31+ userActivity(int displayId, long time, int event, int flags)   // 保亮虚拟屏
              API30-  userActivity(long time, int event, int flags)
wakeUp:       三套签名探测（API29+ / API28 / 兜底 wakeUp(long)），WAKE_REASON_APPLICATION=2
goToSleep:    goToSleep(long,int,int) / goToSleep(long)
```

### WindowManager / DisplayManager / SurfaceControl / StatusBarManager / ActivityManager

- **WindowManager**：`createNewVirtualDisplay(name, w, h, dpi, surface, flags)`（虚拟屏）、
  `freezeRotation(vdId, rot)`、`setForcedDisplaySize`、`clearForcedDisplaySize`、`moveRootTaskToDisplay/moveStackToDisplay`。
- **DisplayManager**（Android 13+ 分叉）：`DisplayManagerGlobal.createVirtualDisplay` / `getDisplayInfo`。
- **SurfaceControl**：`getBuiltInDisplay`、`getPhysicalDisplayIds`、`setDisplayPowerMode(binder, POWER_MODE_NORMAL/OFF)`（物理屏熄/亮）。
- **StatusBarManager**：`expandNotificationsPanel` / `collapsePanels` / `setIconVisibility`（隐藏状态栏图标）。
- **ActivityManager**：`startActivity(Intent, Bundle)`、`forceStopPackage`、`getContentProviderExternal`、`getRunningTasks`、`getPackageInfoNoThrow`。

## 3. Ln：双通道日志（logcat + 终端 stdout/stderr）

引擎进程（app_process / UserService）没有标准 Android 日志树，`Ln` 同时写两处：

```java
public final class Ln {
    private static final String TAG = "RefProject";
    private static final String PREFIX = "[MC] ";

    // 直接绑定进程的 stdout/stderr（root 启动时终端可见；Shizuku 下写 logcat 为主）
    private static final PrintStream CONSOLE_OUT = new PrintStream(new FileOutputStream(FileDescriptor.out));
    private static final PrintStream CONSOLE_ERR = new PrintStream(new FileOutputStream(FileDescriptor.err));

    static Level threshold = Level.DEBUG;

    public static void i(String message) {
        if (isEnabled(INFO)) {
            Log.i(TAG, message);                                  // adb logcat 可见
            CONSOLE_OUT.print(PREFIX + "INFO: " + message + '\n'); // 终端/root 日志文件可见
        }
    }
    // v/d/w/e 同理；w/e 附 throwable.printStackTrace(CONSOLE_ERR)

    public static void disableSystemStreams() {
        // 把 System.out/err 换成 NullOutputStream：MaaCore 内部 println 不污染
        System.setOut(nullStream); System.setErr(nullStream);
    }
}
```

**作用**：
1. root 模式 `--log-file` 重定向 stderr → root_launch_debug.log 能看到引擎日志；
2. Shizuku 模式 logcat 可看到（TAG=RefProject）；
3. 双通道保证"终端/日志文件/logcat"三处都留痕，配合 ServiceBootLogger/RemoteBootTrace 定位。

## 4. wrappers 设计模式总结

```
每个 wrapper：
1. create()：通过 ServiceManager.getService(name, type) 或 FakeContext.getSystemService 拿底层接口
2. 反射方法缓存为 static Method 字段（只反射一次）
3. 多版本签名探测（isScreenOn/wakeUp/userActivity 按 SDK 分支）
4. 失败 Ln.e + 返回默认值，绝不抛到上层
```

## 5. 给复现者的要点清单

1. 引擎进程可用 `ServiceManager.getService` 反射拿任意系统服务（shell/root 豁免 hidden API）。
2. 触摸注入关键：`InputEvent.setDisplayId`（目标屏）+ `injectInputEvent`（WAIT_FOR_FINISH 用于 DOWN）。
3. 保亮：`IPowerManager.userActivity(displayId, ...)`（API31 签名）。
4. 物理屏熄亮：SurfaceControl.setDisplayPowerMode；虚拟屏：WindowManager.createNewVirtualDisplay。
5. Ln 双通道（logcat + FileDescriptor.out/err），并可用 disableSystemStreams 屏蔽 MaaCore 内部 stdout。
6. 反射方法一律缓存静态字段 + 多版本探测 + 失败兜底。
