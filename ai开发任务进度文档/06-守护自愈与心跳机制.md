# 参考项目 深度拆解 06：守护自愈与心跳机制

> 项目"不残留、不死锁、自恢复"的三层守护体系：App 进程侧 UnifiedStateDispatcher、
> 引擎进程侧 heartbeat 看门狗 + shutdown hook、运行期 AppWatchdog（游戏存活/显示漂移）。

---

## 1. 三层守护总览

| 层 | 组件 | 守护什么 | 触发动作 |
|---|---|---|---|
| 连接层 | RemoteServiceManager | 引擎进程 binder | 状态机 Died/Error → UnifiedStateDispatcher 收尾 |
| 引擎进程 | heartbeat watchdog | App 进程存活 | App 死 → 引擎自杀 + 紧急清理 |
| 引擎进程 | shutdown hook | 任何退出路径 | performEmergencyCleanup（恢复音频/释放虚拟屏/销毁 MaaCore） |
| 运行期 | AppWatchdog | 游戏进程存活 / 游戏是否在虚拟屏 | 游戏死 → 上报；漂移 → 宽限期后拉回，上限 3 次 |

---

## 2. UnifiedStateDispatcher：连接状态 → 全局收尾

单线程协程分发器（`Executors.newSingleThreadExecutor().asCoroutineDispatcher()`），
观察 `RemoteServiceManager.state`：

```kotlin
RemoteServiceManager.state.drop(1).collect { state ->
    when (state) {
        Connected -> onServiceConnected(srv) {
            // 授权必授权限 + 同步运行模式到引擎
            permissionManager.grantRequiredPermissions(srv)
            srv.setVirtualDisplayMode(appSettings.runMode.value.displayMode)
        }
        Died      -> onServiceDied() { resourceLoader.reset(); _serviceDiedEvent.tryEmit(Unit) }
        Error     -> onServiceError(e) { _serviceDiedEvent.tryEmit(Unit) }
        Disconnected -> onServiceDisconnected() { resourceLoader.reset() }
    }
}
```

- `serviceDiedEvent` 被 MaaCompositionService 收集 → `appWatchdog.stopWatching() + state=ERROR + sessionLogger.completeSessionAndWait("SERVICE_DIED") + notificationCenter.notifyServiceDied()`。
- **自动资源加载门**：`combine(serviceState, resourceInitState)`，服务 Connected + 资源 Ready 且资源未加载 → 自动 `resourceLoader.load()`（进程启动即可走通，不依赖 UI）。
- 客户端切换 → 自动重载资源。

## 3. 引擎进程 heartbeat 看门狗

```kotlin
override fun heartbeat(pid: Int) { appPid.set(pid) }   // App 侧喂 pid

private fun startHeartbeatWatchdog() {
    Thread {
        while (!destroyed.get()) {
            Thread.sleep(5000)
            val pid = appPid.get()
            if (pid <= 0) continue
            if (!File("/proc/$pid").exists()) {
                destroy(); return@Thread
            }
        }
    }.apply { isDaemon = true }.start()
}
```

- App 绑定成功立即 `service.heartbeat(Process.myPid())`；
- Root 模式由 `RootServiceStarter.primeHeartbeat` 提前喂；
- **作用**：App 被 force-stop / 崩溃时，引擎 5s 内自毁，杜绝孤儿引擎进程占用虚拟屏/权限。

## 4. shutdown hook + performEmergencyCleanup

```kotlin
// RemoteServiceImpl init
Runtime.getRuntime().addShutdownHook(Thread {
    runCatching { performEmergencyCleanup() }
}.apply { name = "remote-shutdown-hook" })

fun performEmergencyCleanup() {
    runCatching {
        GameAudioMuteController.restoreAll()   // 恢复被静音的游戏（防止游戏永久静音）
        PowerController.destroy()              // 释放唤醒锁/停止保亮
        ScreenManager.destroy()                // 还原强制显示尺寸
        MaaCoreManager.destroy()               // AsstDestroy
    }
}
```

**为什么重要**：参考项目 的 `force_stop=true` 会让 MaaCore 连接时强杀游戏，游戏启动前会静音；若引擎进程被系统/看门狗强杀，shutdown hook 仍会执行清理，恢复游戏音量、还原显示、销毁 MaaCore 句柄——**任何退出路径都干净**。

## 5. AppWatchdog：运行期守护（后台模式）

启动时机：`appendTasksAndStart` 成功且 `mode == BACKGROUND` → `appWatchdog.startWatching()`。

```kotlin
enum class WatchdogState { IDLE, WATCHING, APP_DIED }

startWatching():
  packageName = Packages[clientType]
  state = WATCHING
  watchJob = scope.launch {
      while (isActive) {
          delay(5000)
          when (checkAppAliveStatus(pkg)) {
              ALIVE   -> checkDisplayPinned(pkg)     // 检查是否还在虚拟屏
              DEAD    -> { state=APP_DIED; _appDiedEvent.tryEmit(pkg); return }
              UNKNOWN -> 警告，继续
          }
      }
  }
```

### 显示漂移检查（checkDisplayPinned）——带宽限期与重试上限

```kotlin
internal suspend fun checkDisplayPinned(packageName) {
    val onDisplay = appAliveChecker.isAppOnBackgroundDisplay(pkg) ?: return
    if (onDisplay) { 漂移状态清零; return }          // 正常在虚拟屏

    if (driftRepinAttempts >= MAX_REPIN_ATTEMPTS) return   // 3 次上限，停止重试

    val now = clock()
    if (driftFirstSeenMs == 0L) { driftFirstSeenMs = now; return }   // 首次发现，记时间
    if (now - driftFirstSeenMs < REPIN_GRACE_MS) return              // 5s 宽限期

    if (appAliveChecker.moveAppToBackgroundDisplay(pkg) == true) {   // 拉回成功
        清零漂移状态; return
    }
    driftRepinAttempts++
    if (driftRepinAttempts >= MAX_REPIN_ATTEMPTS && !driftNotified) {
        driftNotified = true
        _displayDriftEvent.tryEmit(pkg)                              // 上报（只报一次）
    }
}
```

设计要点：
- **REPIN_GRACE_MS=5s 宽限期**：游戏启动后的 SDK 登录/鉴权弹窗可能导致瞬时"离开虚拟屏"，宽限期避免误拉回打断登录。
- **MAX_REPIN_ATTEMPTS=3**：连续拉回失败即停（拉回会重投放启动 intent，无限重试等于每 5s 投放一次启动请求）。
- 回到虚拟屏后计数清零，下次漂移重新处理。
- `displayDriftEvent` 由 MaaCompositionService 收集 → 日志警告（"游戏离开虚拟显示器"）。

## 6. 给复现者的要点清单

1. 连接状态统一由单线程 dispatcher 收口，Died/Error 统一收尾（停看门狗、置 ERROR、写日志、通知）。
2. 引擎侧 heartbeat + `/proc` 看门狗：App 死则引擎 5s 内自杀。
3. shutdown hook + performEmergencyCleanup：恢复音频/释放虚拟屏/销毁 MaaCore，任何退出路径干净。
4. 后台模式 AppWatchdog：游戏进程存活 + 显示漂移双检测。
5. 漂移拉回要带宽限期（5s）和重试上限（3 次），避免误拉回打断登录、避免无限重投放。
