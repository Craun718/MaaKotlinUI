# 参考项目 深度拆解 04：任务编排与执行

> 从用户点击"开始任务"到 MaaCore 跑起来的完整编排，以及运行期回调分发、前台通知、会话日志。

---

## 1. MaaCompositionService：任务编排核心

依赖注入大量协作者（resourceLoader、appSettings、gameMuteCoordinator、sessionLogger、appWatchdog、taskChainStatusTracker、notificationCenter、dropsRefresher、toolboxResultCollector 等）。

### 运行状态机

```kotlin
enum class MaaExecutionState { IDLE, STARTING, RUNNING, STOPPING, ERROR }
private val _state = MutableStateFlow(MaaExecutionState.IDLE)
```

- 进入 STARTING 时拉起 `TaskExecutionService`（前台服务）：
  ```kotlin
  if (state == STARTING) TaskExecutionService.start(context)
  ```
- STOPPING 期间回调不回 IDLE，由 `finishStop()` 统一收口。

### StartResult 分级（错误可诊断）

```kotlin
sealed class StartResult {
    Success(version)
    ResourceError(exception)              // 资源加载失败
    InitializationError(phase)            // CREATE_INSTANCE / SET_TOUCH_MODE
    ConnectionError(phase, shizukuAsRoot) // DISPLAY_MODE / VIRTUAL_DISPLAY / MAA_CONNECT
    StartError                            // AsstStart 失败
    PortraitOrientationError              // 前台模式竖屏
    InvalidAspectRatioError               // 前台模式非 16:9
    ServiceConnecting                     // 服务连接中，拒绝启动
    RemoteAccessUnavailable(backend)      // 后端不可用
}
```

### start() 主流程（executeStart）

```kotlin
sessionLogger.startSession(...)
subTaskHandler.resetSessionState()
toolboxResultCollector.onSessionStart()
...
return withContext(Dispatchers.IO) {
    checkPreconditions(mode)?.let { return@withContext it }

    setRunState(STARTING)                       // → 拉起前台服务

    useRemoteService { service ->
        val maa = service.maaCoreService
        ensureMaaInstance(maa)?.let { return@useRemoteService it }

        setupDisplayAndConnect(service, maa, mode, clientType)?.let { return@useRemoteService it }

        val result = appendTasksAndStart(maa, tasks, successMessage, mode)
        if (result is Success) taskChainState.saveLastUsedClientType(clientType)
        result
    }
}
```

### checkPreconditions（启动前置检查）

```kotlin
// 1. RemoteServiceManager.state 是 Connecting → 拒绝（避免与后台自动 load 并发）
// 2. RemoteAccessCoordinator 后端可用且已授权 → 否则拒绝
// 3. activityManager.runIfDirty { resourceLoader.load() } + ensureLoaded()
// 4. 前台模式：必须横屏且 16:9（MAA 识别要求）；后台模式走虚拟屏自带 16:9
```

### setupDisplayAndConnect（显示 + 连接）

```kotlin
service.setVirtualDisplayMode(mode.displayMode)          // 前台=PRIMARY / 后台=BACKGROUND
val config = when (mode) {
    FOREGROUND -> {
        val displayId = service.startVirtualDisplay()    // 物理屏模式
        buildConnectConfig(screenW, screenH, displayId)
    }
    BACKGROUND -> {
        val r = resolveAndSetResolution(service, clientType)   // 后台分辨率（可配）
        val displayId = service.startVirtualDisplay()          // 虚拟屏
        buildConnectConfig(r.width, r.height, displayId)
    }
}
grantGameBatteryExemption(clientType)        // 提前给游戏省电豁免+后台不受限
maa.SetInstanceOption(DEPLOYMENT_WITH_PAUSE, ...)
return asyncConnect(maa, config)
```

- 虚拟屏启动失败时区分：`shizukuAsRoot`（Shizuku root 运行但虚拟屏失败 → 提示改用内置 Root 模式）。
- `resolveAndSetResolution`：按客户端类型 + 用户偏好解析后台分辨率（默认 1280x720@160 等）。

### appendTasksAndStart

```kotlin
taskChainStatusTracker.clear()
tasks.forEach { t ->
    val taskId = maa.AppendTask(t.type.value, t.params)
    if (taskId > 0) {
        taskChainStatusTracker.register(taskId, t.type.value, t.slot)   // 注册进度跟踪
        t.slot?.let { dropsRefresher.bind(it, taskId) }
    }
}
if (!maa.Start()) → StartError
setRunState(RUNNING)
if (mode == BACKGROUND) appWatchdog.startWatching()   // 后台模式启动守护
```

### stop() 流程

```kotlin
setRunState(STOPPING)
useRemoteService { service ->
    val maa = service.maaCoreService
    if (!maa.Running()) return finishStop(Success)
    if (!maa.Stop()) return finishStop(Failed)
    // 轮询等 Core 真正停止，60s 超时
    while (maa.Running() && elapsed < 60_000) { delay(100); elapsed += 100 }
    finishStop(if (maa.Running()) Failed else Success)
}
// finishStop: appWatchdog.stopWatching() + state=IDLE + sessionLogger.endSession
```

### stopVirtualDisplay（收尾）

```kotlin
appWatchdog.stopWatching()
service.stopVirtualDisplay()
// finally: gameMuteCoordinator.unmute() 恢复游戏音量
```

## 2. 回调体系（maa/callback）

`MaaCoreServiceImpl.nativeRef`（AsstApiCallback）→ App 侧 `MaaCompositionService.handleCallback(msg, json)` → `callbackDispatcher.onEvent(msg, json)`。

```kotlin
fun handleCallback(msg: Int, json: String?) {
    if (onAsyncConnectCallback(msg, json)) return   // AsyncCallInfo 先喂给 connectDeferred
    callbackDispatcher.onEvent(msg, json)           // 其余交给分发器
}
```

回调分发器（MaaCallbackDispatcher）按消息类型分发到多个处理器：
- `MaaExecutionStateHolder`：任务运行状态（TaskStart/TaskChainStart 等 → RUNNING/IDLE）
- `TaskChainStatusTracker`：每个 TaskChain 的进度/状态（COMPLETED/IN_PROGRESS/ERROR），驱动前台通知进度条
- `SubTaskHandler`：子任务处理（如自定义行动）
- `ToolboxResultCollector`：工具箱结果收集
- `FightDropsRefresher`：掉落统计（TaskChainStart 后回写参数）
- `MaaEventNotifier` / `MaaNotificationCenter`：事件通知

### FightDropsRefresher（掉落刷新）

任务开始（TaskChainStart）后回调里回写"作战掉落"相关参数，动态刷新识别目标——所以 **MaaCore 回调必须先转发再记日志**。

## 3. TaskExecutionService：前台服务 + Live Update 通知

```kotlin
class TaskExecutionService : Service() {
    // 三个数据源合并成快照流：state + taskChainStatusTracker.tasks + sessionLogger 最后一条日志
    combine(compositionService.state, tracker.tasks, logger.logs.last) { ... }
        .distinctUntilChanged()
        .collect { snapshot ->
            when (snapshot.state) {
                IDLE/ERROR -> handleTerminalState(snapshot)   // 停止前台+stopSelf
                STARTING   -> forceUpdate("任务启动中…")
                STOPPING   -> forceUpdate("任务停止中…")
                RUNNING    -> throttledUpdate(...)            // 1s 节流
            }
        }
}
```

- **必须先 startForeground 再做任何可能 stop 的逻辑**（避免 FGS 竞态被系统杀）。
- 通知用 `NotificationCompat.ProgressStyle`（分段进度条 + 不同颜色：完成绿/活动蓝/错误红）。
- 终态退出由服务观察状态流自行 stopSelf（不提供外部 stopService，防竞态）。

---

## 4. MaaSessionLogger：会话日志

- `startSession(taskTypes)`：创建会话（时间戳 + 任务清单）
- `appendAndWait` / `append`：写日志（内存 + 磁盘）
- `completeSessionAndWait(status, msg)` / `endSession(status)`：收尾并落盘
- 会话日志文件按时间戳命名，供导出。

## 5. 给复现者的要点清单

1. 任务编排单入口 `MaaCompositionService.start()`，StartResult 分级（资源/初始化/连接/运行）便于定位。
2. 前置检查：服务非 Connecting、后端授权、资源就绪、前台 16:9 横屏。
3. 显示层失败要区分 `shizukuAsRoot`（提示切 Root）。
4. 回调先喂 connectDeferred（AsyncCallInfo），再分发；先转发后记日志。
5. 任务进度用 TaskChainStatusTracker 驱动通知分段进度条。
6. FGS 必须先 startForeground 再判断终态，终态由服务自 stopSelf。
7. 停止流程轮询 `maa.Running()` 至多 60s。
