# 参考项目 深度拆解 14：底层细节——回调分发体系与设置持久化

> MaaCore 回调如何分发到各处理器？设置如何用 DataStore + StateFlow 响应式管理？
> 本文覆盖 `MaaCallbackDispatcher`、`TaskChainStatusTracker`、`AppSettingsManager`、`MainActivity` 流程。

---

## 1. 回调消息全表（AsstMsg）

MaaCore 通过 `AsstApiCallback` 回调 `(msg, json)`，MaaCallbackDispatcher 按消息类型分发：

| 消息 | 处理器 | 动作 |
|---|---|---|
| InternalError | handleInternalError | 记日志 |
| InitFailed | handleInitFailed | 置 ERROR + 日志 + 结束会话 |
| ConnectionInfo | ConnectionInfoHandler | 连接状态（Adb/Controller 等） |
| TaskChainStart | TaskChainHandler | 注册任务链开始 |
| AllTasksCompleted | handleAllTasksCompleted | 置 IDLE + 收尾 + 结束会话（不依赖 details） |
| TaskChainError / Completed / Stopped | TaskChainHandler | 单链状态（不终止全局） |
| TaskChainExtraInfo | TaskChainHandler | 任务链附加信息（掉落/进度） |
| AsyncCallInfo | MaaCompositionService | 喂 connectDeferred（连接结果） |
| Destroyed | handleDestroyed | 置 IDLE + 结束会话 |
| SubTaskError / Start / Completed / Stopped / ExtraInfo | SubTaskHandler | 子任务/识别结果/自定义行动 |
| ReportRequest | 预留 | TODO |

**关键设计**：
- `AllTasksCompleted` / `TaskChainStopped` 的收尾**不依赖 details**（JSON 解析失败也不跳过收尾）。
- `TaskChainError` 不终止全局（MaaCore 会继续后续链），由 AllTasksCompleted/Stopped 收口。
- 日志用格式化参数（`"msg=%s, json=%s"`）而非字符串模板——**回调热路径上避免无条件拼接数百 KB 的 SubTaskExtraInfo**。

## 2. TaskChainStatusTracker（进度状态）

```kotlin
enum class TaskRunStatus { PENDING, IN_PROGRESS, COMPLETED, ERROR }
data class TaskRunInfo(taskId, taskChain, status, slot)

class TaskChainStatusTracker {
    private val registry = LinkedHashMap<Int, TaskRunInfo>()
    private val _tasks = MutableStateFlow<List<TaskRunInfo>>(emptyList())
    val tasks: StateFlow<List<TaskRunInfo>> = _tasks.asStateFlow()   // 供 UI/通知

    fun register(taskId, taskChain, slot)    // AppendTask 时注册（PENDING）
    fun updateStatus(taskId, status)          // 回调驱动（IN_PROGRESS/COMPLETED/ERROR）
    fun getNodeId(taskId)                     // 关联 slot 节点
    fun clear()                               // 新任务前清空
}
```

驱动前台通知的分段进度条（TaskExecutionService combine 它 + state + 日志）。

## 3. ConnectionInfoHandler / TaskChainHandler / SubTaskHandler / ToolboxResultCollector

- **ConnectionInfoHandler**：解析 `ConnectionInfo` 消息（Adb/Controller/资源等阶段），记录连接进度。
- **TaskChainHandler**：任务链生命周期（开始/完成/错误/停止），联动 tracker 状态 + 掉落刷新（FightDropsRefresher）。
- **SubTaskHandler**（36KB，最复杂）：子任务级处理——识别结果（SubTaskExtraInfo）、自定义行动回调、复杂按钮（如"公开招募"滑块）、小游戏逻辑等；**所有脚本级交互逻辑集中在这里**。
- **ToolboxResultCollector**：工具箱（公招/干员识别等）结果收集，独立会话。

## 4. AppSettingsManager：DataStore 响应式设置

```kotlin
class AppSettingsManager(context, achievementRepository) {
    // DataStore Preferences：app_settings
    val Context.dataStore: DataStore<Preferences> by preferencesDataStore(name = "app_settings")

    // 所有设置项统一模式：
    // settings(map) → distinctUntilChanged → stateIn(Eagerly, 初始值)
    val runMode: StateFlow<RunMode> = settings
        .map { runCatching { RunMode.valueOf(it.runMode) }.getOrDefault(RunMode.BACKGROUND) }
        .distinctUntilChanged()
        .stateIn(scope, SharingStarted.Eagerly, initialSettings.runMode...)

    suspend fun setRunMode(mode) { dataStore.edit { it[runMode] = mode.name } }

    // 关键设置项（节选）：
    // runMode（前台/后台）、startupBackend（SHIZUKU/ROOT）、debugMode、
    // backgroundResolution（后台分辨率）、forceFullscreenOnVirtualDisplay、
    // tasksOverrideEnabled、muteOnGameLaunch、closeAppOnTaskEnd、
    // deploymentWithPause（SWIPE_WITH_PAUSE）、useHardwareScreenOff、
    // wakeUnlockType/wakeCredential、themeMode、language、fontSizeScale ...
}
```

**设计要点**：
1. **DataStore Preferences**（非 SharedPreferences）：协程原生、类型安全、Flow 支持。
2. **blocking `initialSettings = runBlocking { settings.first() }`**：确保后续 `.value` 不是默认值（启动即读盘）。
3. **每项 = StateFlow**：UI 用 `collectAsStateWithLifecycle` 响应式订阅，改动即时生效。
4. **非法值兜底**：`runCatching { enum.valueOf } .getOrDefault(默认)`。
5. `setCustomBackgroundState`：**成对字段合并一次写入**（避免中间态）。

## 5. MainActivity（Meow 版）流程细节

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    delegate.localNightMode = themeMode.toAppCompatNightMode()   // 启动即应用主题
    val splash = installSplashScreen()
    splash.setKeepOnScreenCondition { !isUiReady }               // SplashScreen 等 UI 首帧

    super.onCreate(savedInstanceState)
    dispatchScheduledLaunchIntent(intent)   // 外部/定时任务 Intent 分发

    doObserveKeepScreenOn()   // combine(taskState, screenSaver, useHardwareScreenOff) → FLAG_KEEP_SCREEN_ON
    doObserveThemeMode()      // themeMode.drop(1) → AppCompatDelegate.localNightMode

    // UI 首帧前把 isUiReady 置 true（移除 OnPreDrawListener）
    window.decorView.viewTreeObserver.addOnPreDrawListener { isUiReady = true; ... }

    setContent {
        // 主题 + 字号缩放（Density 整体缩放，保持系统 fontScale）
        RefProjectTheme(...) {
            CompositionLocalProvider(LocalDensity provides Density(density * scale/100, fontScale=系统)) {
                ProvideInputFocusManager { AppNavigation(backgroundTaskViewModel) }
            }
        }
    }
}

private fun dispatchScheduledLaunchIntent(intent: Intent?) {
    if (LaunchIntentMapper.isShowScheduleIntent(intent)) return   // SHOW 只拉 UI，禁止二次 execute
    LaunchIntentMapper.fromExternalIntent(this, intent)?.let { request ->
        backgroundTaskViewModel.onExternalLaunch(request)         // 外部启动（Tasker/MacroDroid 联动）
    }
}
```

细节：
- **splash 保持**直到 UI 首帧（避免白屏闪烁）。
- **keepScreenOn 三条件合并**：任务活动 / 屏保 / 硬件熄屏功能开启——硬件熄屏开启时前台始终常亮（与任务状态解耦）。
- **外部 Intent 联动**：Tasker/MacroDroid 可发 Intent 触发任务（AUTOMATION.md 文档能力）。

## 6. 给复现者的要点清单

1. 回调分发：按 AsstMsg 枚举分发，收尾不依赖 details，热路径用格式化参数防大 JSON 拼接。
2. TaskChainStatusTracker：LinkedHashMap + StateFlow，驱动通知进度。
3. SubTaskHandler 是脚本交互逻辑核心（识别结果/自定义行动/滑块小游戏）。
4. 设置用 DataStore + StateFlow + Eagerly + 初始值 runBlocking 首读，非法值兜底。
5. 成对设置合并写入，避免中间态。
6. MainActivity：splash 等首帧、keepScreenOn 三条件合并、外部 Intent 分发。
