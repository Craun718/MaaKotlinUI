你是资深 Android 逆向/系统级开发工程师。请根据以下需求，从零实现一个名为 **RefProject**（包名 `com.refproject`）的 Android 应用：**在 Android 设备上原生运行 MAA（明日方舟助手），无需 Root，通过 Shizuku（或 Root）获得 shell 权限，用 JNA 直接调用 libMaaCore.so 完成游戏自动化**。

运行要求：Android 9+，arm64-v8a/x86_64，Shizuku 已运行并授权 或 设备已 Root。

### 总体架构（必须遵守）

采用 **App 进程 + 引擎进程 + Logcat 服务进程** 三进程模型：

```
App 进程（UI/编排/资源/日志汇总）
  │ binder（AIDL: RemoteService / MaaCoreService）
  ▼
引擎进程（Shizuku UserService 或 root app_process）
  ├─ RemoteServiceImpl（无参构造）
  ├─ MaaCoreServiceImpl（JNA 封装 libMaaCore.so）
  ├─ VirtualDisplayManager / PrimaryDisplayManager
  ├─ PowerController / ActivityUtils
  └─ DriverClass（native upcall）
  │ 同进程 JNA
  ▼
libMaaCore.so（MaaFramework）+ libbridge.so（capturer/注入）
```

**硬性规则**：MaaCore 只在引擎进程加载；App 进程通过 AIDL 调用；引擎进程所有路径退出都要紧急清理。

### 阶段 1：项目骨架与依赖

1. Gradle Kotlin DSL，单模块 `app`，minSdk 28，targetSdk 最新稳定。
2. 依赖：Compose（UI）、Koin（DI）、coroutines、kotlinx.serialization/fastjson2、JNA 5.x、
   `dev.rikka.shizuku:api:13.1.5`、`rikka.sui`、`com.github.topjohnwu.libsu:core`（Root Shell）、Timber。
3. AIDL 接口（按需拆分）：
   - `RemoteService.aidl`：主引擎服务（setup/pid/heartbeat/destroy/startVirtualDisplay/setVirtualDisplayMode/
     grantPermissions/isAppAlive/moveAppToVirtualDisplay/setMonitorSurface/touchDown/Move/Up/.../maaCoreService()）
   - `MaaCoreService.aidl`：Asst API 封装（SetUserDir/LoadResource/CreateInstance/DestroyInstance/
     AsyncConnect/Connected/AppendTask/SetTaskParams/Start/Stop/Running/BackToHome/GetImage/GetVersion/...）
   - `ILogcatService.aidl`：startCapture(appPid, servicePid, userDir)
   - `ITouchEventCallback.aidl`、`MaaCoreCallback.aidl`（回调）
4. `MaaApplication`：Koin 初始化 + `postCreateApplication()`（初始化连接/日志/崩溃兜底/定时任务闹钟）。

### 阶段 2：Shizuku 与 Root 双通道连接（最重要，先做对）

实现 `RemoteServiceManager`（单例状态机）+ `ShizukuRemoteServiceConnector` + `RootRemoteServiceConnector`。

**RemoteServiceManager**：
```kotlin
sealed class ServiceState { Disconnected / Connecting / Died / Connected(service) / Error(exception) }
// 全部状态迁移在单一 lock 内；binder 死亡用携带 binder 的 DeathRecipient，身份比对防过期回调
// bind(): 幂等（Connecting 跳过）、先解旧再绑新、委托 backend.connect、启动 20s 超时兜底
// getInstance(): 挂起等待 Connected/Error
// useRemoteService {}: 检查授权 → 切后端 → 拿服务 → action
```

**ShizukuRemoteServiceConnector —— 核心坑点（必须照做）**：
```kotlin
private val serviceTag = UUID.randomUUID().toString()          // 每次 connect 重新随机
private val serviceVersion = AtomicInteger(100)                // 每次递增
// UserServiceArgs(ComponentName(appId, RemoteServiceImpl)).apply {
//     processNameSuffix("service"); daemon(false)
//     tag(UUID.randomUUID().toString())        // ← 随机 tag！
//     version(serviceVersion.incrementAndGet()) // ← 递增 version！
//     debuggable(BuildConfig.DEBUG)
// }
// 每次 connect 用【独立新】ServiceConnection，回调校验 activeBinding?.connection === this
// disconnect: Shizuku.unbindUserService(args, conn, true)   // remove=true 销毁服务端 record
```
**原因**（Shizuku 源码 UserServiceManager）：服务端按 `key=package:tag` 管理 record，
`starting=true` 卡死会导致后续所有绑定超时；随机 tag 保证每次全新 key，根治"首次成功之后全部超时"。

**RootRemoteServiceConnector**：
```
token=UUID；Registry.register(token)；Shell.cmd('liblauncher.so --apk=... --starter-class=RootServiceStarter
 --token=<token> --package=... --class=RemoteServiceImpl --uid=... [--keep-root] --log-file=... &')
等待 ContentProvider 回传 binder（RootServiceBootstrapRegistry.attach → deferred.complete）
disconnect: 调 service.destroy()
```
liblauncher.so 为原生 so（nativeLibraryDir），root 进程经 app_process 启动 `RootServiceStarter.main()`
→ `RootUserService.create()`（反射：(Context) 构造器或无参，强转 IBinder）→ 回传 binder → linkToDeath(App lifecycleBinder)。

**授权**：ShizukuManager（pingBinder/checkSelfPermission/callbackFlow 封装 requestPermission/Sui 检测）；
RemoteAccessCoordinator（按配置选后端，监听状态变化）。

### 阶段 3：引擎进程实现

**RemoteServiceImpl（无参构造）**：
- init：RemoteBootTrace.mark + shutdown hook（performEmergencyCleanup）+ Workarounds.apply() + heartbeat 看门狗。
- 心跳看门狗：App 通过 heartbeat(pid) 喂 pid，每 5s 查 `/proc/<pid>`，App 死则 destroy()。
- performEmergencyCleanup：GameAudioMuteController.restoreAll + PowerController.destroy + ScreenManager.destroy + MaaCoreManager.destroy。
- 双模式：PRIMARY（物理屏）/ BACKGROUND（虚拟屏），setVirtualDisplayMode 切换；
  startVirtualDisplay 后台模式附带 PowerController.startUserActivityKeepAlive。
- grantPermissions：以 shell 身份代授 省电豁免/后台不受限/通知/悬浮窗/无障碍等。

**FakeContext**：引擎侧 Context，`getApplicationContext()=this`、包名冒用 `com.android.shell`、
checkCallingPermission 永远 GRANTED、ContentResolver 用 getContentProviderExternal。

**MaaCoreManager**：`Native.load("MaaCore", MaaCoreLibrary)`（lazy）；先 `System.setProperty("jna.tmpdir","/data/local/tmp")`。

**MaaCoreServiceImpl**：封装 Asst*（CreateInstance 先销毁旧实例；AsyncConnect 异步回调；
GetImage 用 MemoryFile+ParcelFileDescriptor 跨进程传图；**native 回调先转发 App 再写日志**）。

**DriverClass（native upcall）**：
```java
public static boolean startApp(String pkg, int displayId, boolean forceStop) {
    boolean ret = ActivityUtils.startApp(pkg, displayId, forceStop, true);  // 带 displayId
    if (ret) ret = ActivityUtils.ensureAppOnDisplay(pkg, displayId);        // 防漂移拉回
    if (ret) awaitFirstFrame();                                             // 等首帧
    return ret;
}
// touchDown/Move/Up/keyDown/keyUp → InputControlUtils
```

### 阶段 4：MaaCore 加载与资源管理

- **MaaCoreLibrary**（JNA）：完整声明 Asst* 函数。
- **MaaPathConfig**：rootDir/resourceDir/cacheDir/globalResourceDir/overridesDir/debugDir；
  `isResourceReady` = resource 存在且 version.json 的 appVersion == BuildConfig.VERSION_CODE。
- **ResourceInitService**：assets 解压到 resourceDir（先删旧目录→全量解压→markAppVersion→同步 overrides 模板），
  状态机 NotChecked/Checking/Extracting/Ready/Failed。
- **MaaResourceLoader**：`srv.setup(rootDir)` → 多目录叠加 `loadResIfExists`：
  主资源 → cache → global(国际服) → overrides（最后）；`tasks.json → tasks/tasks.json` 兼容；
  失败分级 permanent/临时，ensureLoaded 幂等重试；先异步加载干员/物品/活动表（30s 超时）。

### 阶段 5：任务编排与执行

**MaaCompositionService**：
- 状态机 IDLE/STARTING/RUNNING/STOPPING/ERROR；STARTING 拉起前台 TaskExecutionService。
- start()：sessionLogger.startSession → checkPreconditions（服务非 Connecting、后端授权、资源就绪、
  前台 16:9 横屏）→ setRunState(STARTING) → useRemoteService →
  ensureMaaInstance（CreateInstance + SetInstanceOption TOUCH_MODE=ANDROID）→
  setupDisplayAndConnect（setVirtualDisplayMode → startVirtualDisplay → grantGameBatteryExemption →
  SetInstanceOption DEPLOYMENT_WITH_PAUSE → AsyncConnect）→ appendTasksAndStart（AppendTask×N → Start）。
- stop()：AsstStop + 轮询 Running() 至多 60s → finishStop。
- StartResult 分级（Resource/Initialization/Connection(phase, shizukuAsRoot)/Start/Portrait/Aspect/Connecting/Unavailable）。
- 回调：handleCallback → AsyncCallInfo 喂 connectDeferred，其余 callbackDispatcher 分发
  （MaaExecutionStateHolder/TaskChainStatusTracker/SubTaskHandler/ToolboxResultCollector/FightDropsRefresher/Notifier）。

**TaskExecutionService**：前台服务；combine(state, tasks, lastLog) → Live Update 通知
（ProgressStyle 分段进度条，1s 节流）；先 startForeground 再判断终态，终态自 stopSelf。

### 阶段 6：虚拟屏与双模式

**VirtualDisplayManager**：
- flags：PUBLIC|PRESENTATION|OWN_CONTENT_ONLY|SUPPORTS_TOUCH|DESTROY_CONTENT_ON_REMOVAL
  + Android13+ TRUSTED|OWN_DISPLAY_GROUP|ALWAYS_UNLOCKED|TOUCH_FEEDBACK_DISABLED
  + Android14+ OWN_FOCUS|DEVICE_DISPLAY_GROUP|STEAL_TOP_FOCUS_DISABLED（防冻结黑屏）。
- 旋转：freezeRotation + setForcedDisplaySize（横屏原生设备）。
- setResolution 变化自动 restart；start() 防重入（AtomicInteger 状态）。

**ActivityUtils**：
- startApp(pkg, displayId, forceStop, excludeFromRecents)；startActivity 用 ActivityOptions.launchDisplayId，
  失败回退 `am start --display`。
- ensureAppOnDisplay：轮询 getAppDisplayId（反射 RunningTaskInfo.displayId，取最近任务），
  漂移则 repinAppToDisplay（moveRootTaskToDisplay → am display move-stack → 强制 FULLSCREEN 重投）。

**PowerController**：周期 userActivity 保亮虚拟屏。

### 阶段 7：守护自愈

- UnifiedStateDispatcher：单线程观察 RemoteServiceManager.state → Connected 授权+同步模式 /
  Died/Error → serviceDiedEvent（Composition 收尾：停看门狗、置 ERROR、写日志、通知）；自动资源加载门。
- AppWatchdog（后台模式）：每 5s 检查游戏进程存活（pidof）+ 是否还在虚拟屏；
  漂移 5s 宽限期后拉回，上限 3 次，回到虚拟屏清零。

### 阶段 8：日志与诊断

- ServiceBootLogger（App 绑定链路，512KB 轮转）、RemoteBootTrace（引擎启动 trace，路径自行推导）、
  root_launch_debug.log、LogcatServiceManager+LogcatCaptureServiceImpl（独立进程按 pid 抓 logcat）、
  MaaSessionLogger（会话日志）、LogExportService（打包 ZIP：FileProvider 分享/SAF 写入）。
- CrashHandler 兜底。

### 阶段 9：UI（可后置）

- Compose 首页（引擎状态卡/快捷入口/权限引导/ShizukuReadinessGate）、脚本页（任务列表/日志/预览/开始停止）、
  设置页（运行模式/后端/分辨率/后台保活等）、定时任务页、悬浮窗控制。

## 验收清单（每个阶段完成后自测）

1. **连接**：Shizuku 授权后 20s 内拿到引擎 binder；连 10 次不出现"首次成功之后超时"；引擎崩溃后 App 能自动重连。
2. **资源**：首次启动 assets 解压成功；二次启动跳过；版本号变化强制重解压。
3. **任务**：点击开始 → 游戏启动到目标屏（虚拟屏无黑屏）→ MaaCore 识别跑任务 → 停止干净；
   后台模式息屏不黑屏；游戏被 ROM 挪走能自动拉回。
4. **守护**：强杀 App → 引擎 5s 内自杀且恢复游戏音量；强杀游戏 → 引擎/App 感知并收尾。
5. **日志**：三份 debug 日志可导出 ZIP，能定位"绑不上/起不来/连不上"。

## 避坑清单（血泪经验）

| 坑 | 解法 |
|---|---|
| Shizuku 绑定超时（record.starting 卡死） | 随机 tag + 递增 version + 独立 connection + unbind(remove=true) |
| 引擎侧 `applicationContext` NPE | FakeContext.getApplicationContext()=this；或不用 applicationContext |
| JNA 解包 so 失败 | `jna.tmpdir=/data/local/tmp` |
| 虚拟屏黑屏/冻结 | 带 Android13+ flags（TRUSTED/ALWAYS_UNLOCKED/OWN_FOCUS）+ userActivity 保亮 |
| 游戏从虚拟屏漂移到主屏 | startApp(displayId) + ensureAppOnDisplay + AppWatchdog 兜底 |
| 引擎孤儿进程 | heartbeat + /proc 看门狗 + shutdown hook 紧急清理 |
| FGS 被系统杀 | 先 startForeground 再判断终态；终态自 stopSelf |
| MaaCore 回调丢参数 | 回调先转发 App 再记日志 |
| 引擎启动卡死难排查 | RemoteBootTrace 全程 mark + 三层 debug 日志 |
